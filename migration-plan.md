# Correlation-agent migration plan

## 1. Canonical vocabulary decisions

The project should use one canonical schema for the frontend and downstream ingest:

- Severity: `info | low | medium | high | critical`
- Event type: `deployment | metric | log | alert | error | health | resource | business_failure`
- Source: existing UI source enum or a separate `tool` field, but keep it normalized at the ingestion boundary

Normalization rules:

- `CRITICAL`, `ERROR`, `SEVERE` -> `critical`
- `WARNING` -> `medium` (policy choice: keep `WARNING` as the midpoint between `medium` and `high` unless future product requirements say otherwise)
- `INFO` -> `info`
- dotted event names such as `deployment.completed` or `metric.usage` are translated to the canonical type before persistence

## 2. Mapper contract

The mapper must live at `src/lib/mappers.ts` and should convert the agent payload into the UI-ready `Incident` model.

Responsibilities:

- unwrap nested `time_window` to `startTime`/`endTime`
- scale `correlation_score` from `0..1` to a `confidence` percentage in `0..100`
- derive `severity` from the maximum severity across the incident events
- convert `correlation_reasons` to `evidence[]`
- build `timeline` from `relationships` where `type === "PRECEDES"`
- keep narrative-only fields as placeholders when the payload does not provide them

## 3. Supabase and persistence model

This payload is not a flat event stream. It is an incident bundle. Persist it like this:

### incidents

Store the mapped incident metadata:

- `id`
- `title`
- `severity`
- `confidence`
- `status`
- `service`
- `description`
- `root_cause`
- `start_time`
- `end_time`
- `correlated_count`
- `affected_services` (JSONB or array)

### events

Store the mapped child events as rows that reference the incident:

- `id`
- `incident_id`
- `service`
- `type`
- `source`
- `message`
- `severity`
- `timestamp`
- `metric`
- `value`
- `metadata` (JSONB)

### event_relationships

Store graph edges separately:

```sql
CREATE TABLE IF NOT EXISTS event_relationships (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  incident_id text NOT NULL,
  from_event_id text NOT NULL,
  to_event_id text NOT NULL,
  relationship_type text NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now()
);
```

This avoids collapsing a causal graph into a flat timeline before the UI has chosen whether to render a graph or a single ordered stream.

## 4. Future work checklist

- decide whether to render `relationships` as a linear timeline only or a graph view
- decide whether `corelation-engine/` remains a local fallback or is deprecated
- decide whether `description` and `rootCause` are generated by a separate LLM call or are expected from the agent payload later
- add explicit ingestion service functions for agent output -> mapped incident -> persisted rows

## 5. Operational guidance for the next agent

When a new failure appears:

1. confirm the exact source schema being received
2. map to the canonical vocabulary first
3. validate the mapper with one failing regression test
4. fix one root cause at a time
5. rerun the relevant targeted checks before broad build commands
